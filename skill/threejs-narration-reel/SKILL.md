# ナレーション × Three.js 解説リール

作業場所: このキットのルート（`AGENTS.md` があるフォルダ。以下のパスはすべてここからの相対パス）。python は `.venv/bin/python`。準備は `README.md` の「はじめに」。
完成例: `projects/paradise_tea`（台本・タイミング・計画）と `remotion-composer/src/paradise`（シーン）。

## パターン（最初に決める）
依頼の内容から、どちらのパターンかを最初に決める。`new_project.py` と `scaffold_remotion.py` に `--pattern` で渡す（`script.json` の `"pattern"` に残る）。分からないときはユーザーに聞く。

| | **ai**（AI関連・検定用アカウント「【公式】生成AIみんなの検定」） | **tea**（紅茶の雑学） |
|---|---|---|
| 対象 | 親のための AIライフハック、親子で守る AI防犯など、AI の使い方・AI 犯罪の話 | 「知ってた？紅茶の雑学」シリーズ |
| 完成例 | `projects/chatgpt_kondate`・`src/chatkondate`（2026-10-25） | `projects/paradise_tea`・`src/paradise`、`src/kurenai` など |
| 最後の行 | 「〇〇したい人は、プロフィールからフォローしてください！」のような、プロフィールへ促す1行で終える | プロフィールへ促す行は入れない |
| 終わり方 | **プロフィール導線のカット**で終える（下記） | **プロフィール導線のカットは使わない**。紅茶の導線は未定（2026-10-25 時点）。決まるまでは、まとめのカード（大事な点の見出し）で終える |
| シリーズ帯 | 帯色 RGB 128,242,255・黒文字。最後のカードでは帯を消す | パターン固有の帯（`src/paradise` など）。最後まで出したまま |

### ai パターンの終わり方（プロフィール導線のカット）
- カット構成は `src/chatkondate` と同じ。最後のシーンで締めの絵（例: 夜のひとり時間にくつろぐ親）を見せながら締めの行を読み、**「プロフィールから」のチャンクが始まるところから**導線のカードに切り替えて最後まで出す。
- カードは共通部品 `remotion-composer/src/narration/ProfileCta.tsx` を使う（自作しない）。
  - 絵を暗くし、上に締めの文を2行（1行9文字以内、例:「家事を時短して／夜のひとり時間を」）、その下にアカウントのプロフィール画像（シアンの枠）。画像の「フォロー」ボタンを黄色い枠で囲み、脈打たせる。
  - シーンに `bandOff: (b) => profileBandOff(b.f, ctaAt)` を付けて、**水色の帯と帯の文字を消す**（ユーザー指定、2026-10-25）。
  - カードは y 300〜1410 に収まり、字幕（y 1450〜）にかからない。
- プロフィール画像の原本は `scripts/narration_reel/templates/profile_cta.png`（1055×2000）。`scaffold_remotion.py --pattern ai` が `public/<slug>/profile.png` にコピーする。キットに入っているのは**ダミー画像**。ai パターンを使う前に、自分のアカウントのプロフィール画面のスクリーンショットに差し替える（完成例の `public/{chatkondate,camerahack,mimamorikoe,snsyuukai}/profile.png` もダミー）。投稿数やグリッドが変わったら、新しいスクリーンショットで原本を差し替える。サイズやフォローボタンの位置が変わったら `ProfileCta.tsx` の `PROFILE_SHOT` も直す。

## 固定ルール
- モデル: **Eleven v4**（`eleven_v4`）
- 声: **Otani - Inviting, Clear and Measured**
- タグ: ナレーションの**各行の先頭に `[narrative]`** を付ける。
- 速度: **1.2倍速**。v4 の画面には速度設定が無いため、生成した音声に ffmpeg `atempo=1.2` を掛ける（音程は変わらない）。
- **事前許可**: 元の運用では、このスキルを呼んだ時点でユーザーが次の2つを許可しており、途中で許可を求めて作業を止めなかった。使う人が同じ運用にするかを最初に決め、決めたことをこのキットの `AGENTS.md` に書く（書かれていなければ、生成とダウンロードの前に1回ずつ確認する）。
  - ElevenLabs の利用: `tts_api.py` の実行と、ブラウザでログイン済みの elevenlabs.io での台本入力・「音声を生成」・クレジット消費（このリールの台本の分）。
  - 生成した音声のダウンロード: elevenlabs.io から、このリールのテイク（mp3）を `~/Downloads` に落とすこと。落としたら、ファイル名・サイズ・md5 を作業ログに書くだけでよい。
  - この許可の範囲外（elevenlabs.io 以外からのダウンロード、mp3 以外のファイル、プランの購入・アップグレード、規約への同意、アカウント設定の変更）は、これまでどおりユーザーに聞く。
- 手順は次の3つだけを、この順で行う。

## 台本の設計（ユーザー指定、2026-10-28）
紅茶の雑学 40本の台本が「全体設計・フック・本題からの出だし・深掘りと面白さのズレ」でイマイチだった（全本が「フック→定義→ただし書き→〜してみてください」の同じ4段で、中盤が注意書きに使われていた）。台本は次の順で考える。
- **先に「核」を1文で決める**。核は、視聴者が人に話したくなる一点（名前の由来、意外なつながり、数字、身近なものとの共通点、歴史の皮肉）。「表示を確認」「一律ではない」「店舗ごとに違う」は核にしない。
- **尺**（ユーザー指定、2026-10-28）: **45秒以上**。内容によって60秒・90秒を超えてもよい。文字数は秒数から決める。1.2倍速の Otani は、句読点・記号を除いた字幕の文字数で**1秒あたり約5.5字**（過去の紅茶リール6本で5.0〜5.8字、仕上がり尺で割った値）。目安は、手順・選び方の回が260〜300字（約47〜55秒）、由来・仕組みの回が330〜400字（約60〜72秒）、人物や出来事の物語がある回が430〜500字（約78〜90秒）。45秒未満（約250字未満）にしない。2026-10-28 の初回改訂は「220〜280字（句読点込み）」で書き、40本中39本が45秒未満になった。
- **構成**: 出だし1文 → ひっかかり1〜2文（「なぜ？」を足す。答えはまだ言わない）→ 核を言い切る → 深掘り（核の「なぜ」「具体例」「数字・人名・場面」。尺が長い回ほど、ここを場面や続きの話で増やす。注意書きや一般論で埋めない）→ 締め1文（核の言い換えか、次の一杯で試せる行動を1つ。コメントしたくなる問いも可）。
- **フックの型**: ①答えを言わない問い（「ハイティーの『ハイ』って、何が高いか知っていますか？」）②意外な事実の前半だけ（「国の名前は変わったのに、紅茶だけは昔の名前のまま。」）③身近な場面（「冷蔵庫の紅茶を淹れたら、キムチの香り。」）④数字（「1袋1,000円の紅茶は、1杯にするといくら？」）。
  - NG: 答えを先に言う（「オレンジペコー、オレンジ味の紅茶ではありません。」）、「〜と思っていませんか？」の連発（決めつけになる）、「〜してみませんか」「〜とは限りません」で始める。
- **本題から入る出だし**（フックなし）: 1文目で、題材の名前と意外な一点を一緒に言い切る（良い:「ニルギリという紅茶の名前は、『青い山』という意味です。」／悪い:「ニルギリは南インドの高原で作られる紅茶です。」）。定義や「今回は〜を紹介します」から入らない。
- **深掘りのズレを防ぐ**: 深掘りの各文に「これを聞いて『へえ』と思うか」を問い、思わない文（手順の確認、一般論の注意、核と関係ない豆知識）は削る。留保・注意は台本管理シートの「根拠・注意点」列やキャプションへ移し、ナレーションでは「〜と言われます」の一言まで。安全に関わること（お酒は20歳から、火から目を離さない）だけは1文残す。
- **締め**: 「〜してみてください」「目を向けてみませんか」の一般的な誘いで終えない。核につながる一言にする。同じシリーズで締めの形が続かないよう、並べて確かめる。
- 例と改訂前後の全文: `docs/紅茶台本の改訂_見比べ_2026-10-28.md`（40本の改訂前後と核・型・文字数）。

## 1. ElevenLabs で音声を生成する（1.2倍速）
1. `scripts/narration_reel/new_project.py <name> --title "..." --pattern ai|tea` を実行する。テーマの事実を調べ、`projects/<name>/script.json` に台本を書く。上の「台本の設計」に沿って書く。
   - ai パターンは、最後の行をプロフィールへ促す1行にする（ユーザーの原稿があればそのまま使う）。tea パターンには入れない。
   - 書き方: シーン → 行 → `[字幕, 読ませる文]` のチャンク。字幕は11文字以内で文節ごとに区切る。数字や誤読しやすい語は、読ませる文の側で読み方を指定する。
   - 調べた出典は `sources` に記録する。裏付けの弱い内容は「〜とも言われます」とぼかす。
   - 比べる話は途中の一段を省かず声に出す（悪い例: 「英語ではブラックティー。中国で黒茶は別のお茶」／良い例: 「英語では…「ブラックティー」と呼ばれます。直訳すれば「黒茶」ですが、「黒茶」といえば、中国などではプーアル茶など別のお茶のことです。」）。
   - 脇道の話題のあとにいきなり締めない。締めの前の1行で本題に戻し（例: 「葉の色を見た英語に対して、「紅茶」はお茶の色を見た名前なんです。」）、締めはその行から続く内容にする。音声を作る前に、最後の3行を続けて読んでつながりを確かめる。
2. `scripts/narration_reel/ui_text.py <name>` で、各行に `[narrative]` が付いた本文を出力する。
3. 生成する。
   - まず `scripts/narration_reel/tts_api.py <name>` を試す。今の API キーは無料プランのため、ライブラリ音声は 402 エラーになる。
   - 402 になったら、ブラウザで `https://elevenlabs.io/app/speech-synthesis/text-to-speech` を開く。ブラウザを操作できるエージェント（元の運用は Claude in Chrome）なら以下を自分で行い、できなければ以下の手順をユーザーに伝えて、ダウンロードした mp3 のパスをもらう。
     - 初めて使う Chrome プロフィールでは、2本目のダウンロードを Chrome が「複数ファイルの自動ダウンロード」としてブロックする。エージェントはこの設定を変えない。止まるのはこのブロックが原因で、エージェントの確認ではない。このプロフィールで生成を始める前に1回だけ、ユーザーに「`chrome://settings/content/automaticDownloads` の『許可』に `elevenlabs.io` を追加してください」と伝え、追加されてから生成する。済んだプロフィールは、ここに書き足しておく。
     - ボイス検索で「Otani」を探し、「使用」を押す。モデルが Eleven v4 になっていることを確認する。
     - 本文を1行ずつ入力し、行の間で Enter を押す（`[narrative]` はタグとして認識される）。
     - 「音声を生成」を押す（2テイクできる）。
     - 2テイクをダウンロードする。固定ルールの「事前許可」で許可を取ってあれば、確認せずに続ける。落としたファイルの名前・サイズ・md5 を `ls`・`md5` で確かめて記録する。
     - 自動ダウンロードの許可を追加してもらったら、そのタブを**再読み込みしてから**落とす（再読み込みの前は、ボタンでもページ内のリンクでも1本も落ちなかった）。生成直後にカードの「再生」→ JS で一時停止 →「オーディオをダウンロード」を、テイク1・2の順に行う。履歴の行からはテイク1しか読み込めないので、生成直後に2テイクとも落とす。落ちたかは `ls ~/Downloads/ElevenLabs_*` で確かめる（名前の時刻はコロンが「_」に置き換わる）。自分で付けた名前だけを探して見落とし、同じテイクを二重に保存したことがある（`projects/english_breakfast`、2026-10-30）。
4. `scripts/narration_reel/prepare_take.py <name> ~/Downloads/<file>.mp3 --take N` で、テイクをプロジェクトに取り込み、1.2倍速にする。
   - **長いナレーション（目安 300 文字超）は分けて生成する**（長いと精度が下がる）。`script.json` の `"parts"` にシーン ID のまとまりを書くと、`ui_text.py` がパートごとの本文を出す。パートごとに生成して2テイクずつダウンロードし、`scripts/narration_reel/join_parts.py <name> part1.mp3 … partK.mp3 --take N` でつなぐ（頭と尻の無音を詰め、行間と同じ 0.85 秒の間を入れる）。その後 `prepare_take.py <name> --take N` を実行する。全テイク1でつないだ take1、全テイク2でつないだ take2 を Scribe で確認し、パートごとに良いほうを選んで take3 としてつなぎ直す（完成例: `projects/ai_mukae`）。
5. `scripts/narration_reel/stt_check.py <name> 1 2` を実行し、Scribe で誤読がないか確認する。
   - 表記の違い（「一つ」と「ひとつ」など）は問題ない。
   - 誤読があれば台本の読み方を直し、生成からやり直す。
   - 誤読のないテイクのうち、間の自然なほうを採用する。
   - Scribe の API キーのアカウントがクレジット切れ（401 quota_exceeded）のときは、`scripts/narration_reel/stt_whisper.py <name> 1 2` を使う（`whisper-cli` と、モデル `models/ggml-large-v3-turbo.bin` または環境変数 `WHISPER_MODEL` が要る）。whisper.cpp（large-v3-turbo）で文字起こしし、Scribe と同じ形の `take<N>_x.stt.json` を書くので、`build_timeline.py` はそのまま動く。数字は「2020」「54%」と算用数字で返るので、`spelling` に「"2020": "二千二十"」のように足す（`projects/english_breakfast` は 477/477 字が対応）。
6. `scripts/narration_reel/build_timeline.py <name> <take> --slug <slug>` で、チャンクごとの開始時刻を声の立ち上がりに合わせる。
   - `public/<slug>/narration.wav` と `timeline.json`、`projects/<name>/timing.md` ができる。

## 2. ナレーションのタイミングに合わせて、1行ずつ Three.js のアニメーション計画を作る
`timing.md` の時刻を使い、`projects/<name>/animation_plan.md` を書く（書式は `projects/paradise_tea/animation_plan.md` を参照）。
- 冒頭: 音声の設定、全長、アートディレクション、デッドゾーンを書く。アートディレクションは、構図 → 光 → 素材 → 動き → 後処理の順に決める。
- 表: ナレーション1行ごとに1行。列は「時刻／ナレーション（チャンクの開始時刻）／3Dの動き／カメラ／テロップ・効果音」。動きの切り替わりは、そのチャンクの時刻に合わせる。
- デッドゾーン: シリーズ帯は y 276–472、字幕は y 1450 から幅 800 px（x 140–940）。主役とテロップは x 140–940 / y 490–1420 に収める。
- 0秒から絵が動く（フェードインしない）。
- 「※AI制作のアニメーションです」などの AI 制作の注記は**入れない**（ユーザー指定、2026-10-24）。過去の完成例（`src/paradise`・`src/golden2` の outro、`src/aimukae/overlays.tsx` を使う `src/aimukae`・`src/kondate`）の最後のカードには注記が残っているので、シーンや部品を流用するときは注記の行を消す（`src/royalmilk` は削除済み）。

## 3. アニメーションを生成する
1. `scripts/narration_reel/scaffold_remotion.py <name> --slug <slug> --comp <CompId> --series "<シリーズ帯の文言>"` を実行する（パターンは `script.json` から読む。`--pattern ai|tea` で上書きできる）。
   - `remotion-composer/src/<slug>` に仮のシーンが作られ、`Root.tsx` に登録される。
   - ai パターンでは、最後のシーンにプロフィール導線のカードが入った状態で作られる。`CTA_LINE` / `CTA_CHUNK`（「プロフィールから」のチャンク）と `LINES`（締めの2行）を埋め、締めの絵を描く。
2. 計画どおりに `src/<slug>/scenes/<id>.tsx` を書く。効果音は `cues.ts` に書く。
   - 3Dの部品は `src/paradise/three` から使う: ステージ、ポスト処理（被写界深度・ブルーム・ACES）、香りの帯・グロー・きらめき、グラス、花、果物、小物。
   - テーマ専用の部品は `src/<slug>/three` に作る。
   - 毎フレームの絵はフレーム番号だけで決める。時刻は `b.ck(行, チャンク)` で参照する。
3. 静止画で確認する（`cd remotion-composer && COMP=<CompId> node golden-stills.mjs <出力先> <frame...>`）。代表フレームを並べて、次を見る。
   - 構図・露出・色・デッドゾーン
   - 字幕と絵の内容が一致しているか
4. 書き出す。
   - `npx remotion render <CompId> ../projects/<name>/renders/v1_raw.mp4 --gl=angle --concurrency=6`
   - その後 `ffmpeg … -af loudnorm=I=-14:TP=-1.5:LRA=11` で `final.mp4` にする。
5. 完成した動画を確認してから渡す。
   - 2fps のコンタクトシートで、各行の絵とナレーションが合っているかを視聴者の目で確認する。
   - 最終音声を Scribe で文字起こしし、台本どおりか確認する。
   - `grep -rnE "AI制作|AiNote" remotion-composer/src/<slug>` が何も返さないこと（AI 制作の注記を入れない）。
   - ai パターン: 最後のカードでプロフィール画像が出て、水色の帯が消えていること。`grep -rn ProfileCta remotion-composer/src/<slug>` が最後のシーンを返すこと。
   - tea パターン: `grep -rn ProfileCta remotion-composer/src/<slug>` が何も返さないこと（プロフィール導線を使わない）。
6. 記録を残す（エージェントのメモリには書かない。ユーザー指定、2026-10-27）。
   - そのリールの状態・経緯・数値（尺、ラウドネス、採用テイク）は `projects/<name>/animation_plan.md` の「仕上がり」に書く。
   - 次のリールでも使えるコツ・部品・読み方は、このスキルの「気をつけること」に書く。ユーザーのFBは、当てはまる節（固定ルール・台本の書き方など）に書く。
   - エージェントのメモリに、リールごとの記録を作らない。ユーザーには、どのファイルに書いたかを伝える。
6. 渡すとき: `final.mp4` が 30 MB を超えるとスマホに送れないので、`-b:v 2600k` で再圧縮した `final_share.mp4` を送る（90 秒を超える尺は 2600k でも 30 MB を超えるので 2100k にする。`projects/sns_yuukai` は 91.9 秒で 2100k・約 26 MB）。投稿には元の `final.mp4` を使うよう伝える。

## 気をつけること（これまでのリールで分かったこと）

### 光・構図・素材
- 明るいシーンはすぐ白っぽくなる。補助光は弱めに（半球光 0.45 / 正面 0.55 / 環境 0.5）し、テーブルにも色を付ける。
- 透明な液体は、暗い色＋自己発光＋弱い鏡面反射にする。そうしないとピンクに見える。
- 加算合成の帯は、HDR の強さを 0.5 程度に抑える。強すぎると ACES で白く飛ぶ。
- 9:16 では横一列に並べた物が入りきらない。奥行きをずらして縦に重ねる。
- 奥に置いた背の高い器は、カメラ高さ 3 前後だと液面が縁に隠れて「空の器」に見える。液面を縁の 0.1 以内まで上げ、カメラを y 3.8 程度まで上げる（`src/chaimilk` のクルハド）。2つの器の真ん中に小物を浮かせると奥の器に重なるので、手前の器の奥など空いた所に置く。
- 白い皿に盛った小さな粒（CTC など）は、寄りの被写界深度で皿の白が混ざってベージュに見える。粒の色はほぼ黒（#1c0c05 前後）・roughness 0.9 にし、自己発光は 0.1 以下にする。
- 横に広い地図（ペルシャ〜日本など）は、点が x 140–940 いっぱいに並ぶ。端の点のラベルは点の真上に置かず、内側へ 60〜100 px ずらす（`src/chaimilk/scenes/name.tsx`）。
- 3D の物の横に名前のチップを並べるとき（スタンドの段など）は、物を画面の中央に置かず、注視点を横にずらして物を左寄せにし、右の空きにチップを置く。中央に置くと左右どちらにも 140–940 の中に収まらない。2つのテーブルの引き（WIDE）で高さの矢印を出すときは、テーブルの横ではなく**手前の辺の中央**から立てる（横だと画面の外に出るか、手前のソファに重なる）（`src/teatimes`）。
- 家具のある部屋（テーブル・ソファ）は、カップの scale 0.13 を実寸（1 単位 ≈ 0.7 m）にそろえる。0.22 にすると皿が 30 cm になり、料理が家具より目立つ。9:16 は横が約 0.3×距離しか入らないので、幅 1.7 のソファは距離 7 で画面いっぱいになる。2つのテーブルを比べるカットは、x を ±0.6 以内に寄せて奥行きでずらし、カメラ距離 約10 にする（`src/hightea`）。
- テーブルに寄るカットは、カメラを天板より 2.2〜2.5 上・3.3〜3.9 手前に置き、注視点を天板の 0.15〜0.2 下にすると、天板が画面の中央に来る（低い位置から撮ると天板が上に寄り、下半分が脚と床になる）。別のセットの家具が手前に映り込むので、そのカットでは描かない。
- 木のテーブルを光らせる自己発光は 0.07 以下にする（0.25 だと昼の光で黄色い板になる）。
- 主役のグラスなどは、使える範囲（y 490–1420）の約半分の大きさにする。fov 30 でカメラ距離 7〜8 程度。
- 9:16 は横の画角がとても狭い（fov 30 の横は約 17°）。並んだ人物2人を真横から撮ると、どちらも画面に入らない。カメラ位置は勘で決めず、`project2` と同じ計算で各点の画面座標を出し、y 490–1420 / x 140–940 に収まる距離と角度を総当たりで求める。`scripts/narration_reel/cam_search.py` が、点の一覧と y の範囲（下にカードを置くなら y 500–880 など）から候補を出す。注視点を上げると物は画面の下へ、下げると上へ動く（`projects/english_breakfast` は全カットこれで決め、帯に隠れる・カードに重なるが一度で直った）。
- 町のジオラマでは、高めの斜め上（仰角 20〜35°）から撮ると、人物と町が一緒に入って模型らしく見える。地図のように場所を一度に見せたいときは、町を引きで撮らず、テーブルに置いた絵地図（キャンバステクスチャ）にピンを立てる。
- 起きている子どもと棚の見守りカメラを1画面に入れる部屋のカットは `src/mimamorikoe/scenes/cams.ts` の `ROOM_CAM`（距離 約7.2、カメラ y 1.6）。`camerahack` の `HOOK_CAM`（距離 約9.5）だと棚のカメラが小さく、上から撮ると帯に隠れる。吹き出しはカメラの真上でなく右横（`Bubble` の dx 250・dy −60 前後）に出す。
- `aimukae` の人形の `crouch` を 0.3 より上げると、脚が前に出て空気いすに座っているように見える。子どもに話しかける親は `crouch` を使わず `lean` 0.35〜0.4 で前かがみにする。
- 研究室（濃紺の無限背景）のカットは、カメラを固定の型（`src/aimukae/scenes/cams.ts` の `LAB_CAM`）にそろえ、物は y 0〜2.6 に置く。こうすると帯にも字幕にもかからない。
- 町の明かり（店のガラス、街灯）は、被写界深度でぼけると大きな白いもやになる。自己発光は 0.3〜1.4 程度に抑える。
- 「光にかざす」表現は、カメラを約20°上から構えて液面を見せ、窓は画面の外に置く。光は、カウンターに落ちたぼけた窓の形、急角度の後ろからのスポット（浅い角度だと塗装したカウンターが照り返す）、グローで表す（`src/kurenai` の `SunLight`）。
- 近すぎるカメラは頭が帯に隠れる。人物は距離 6.4〜7 程度まで引く。鍋とバーナーは距離 8〜9。2つの飲み物を並べた締めは、カードを y 490–860 に収め、距離 約11.6。
- カメラのキーは直線で補間されるので、途中で壁や建物に入らないか中間フレームも見る。
- 下からせり上がる物は字幕の帯を横切る。動きは 0.2 以内にして、拡大で出す。
- 浮かんでいる物と、discard で形を抜いた板（葉など）は `castShadow` しない（大きな影や四角い影が落ちる）。
- metalness 1 の金属は、環境マップがないと真っ黒になる。metalness 0.35 程度に弱い自己発光を足す。`royalmilk` の Pitcher の `steel` も、カフェのカウンターでは真っ黒に見える。お湯を注ぐ場面でも白い磁器のピッチャー（`steel` なし）を使う（`projects/teabag_shiboru`）。
- `golden2` の Drop は `tint` を付けても透明なガラス玉に見え、濃い紅茶のしずくにならない。不透明な濃い液体のしずくは `teabag/three/teabag.tsx` の DarkDrips（中の TeaDrop：#3a1206・クリアコート）を使う。
- カップの上に吊るした物と2行の見出しを同じ画面に入れるときは、先にカップ・吊るした物の上端・受け皿の手前を `project2` と同じ式で画面座標に直し、見出し（y 500–720）と物（y 730–1340）が重ならない注視点を決める。勘で決めると見出しが物にかぶる（`teabag` の HERO：カメラ [0.3, 3.3, 9.2]・注視点 y 0.72、カップ 0.75 倍）。
- 白いクリアコートの皿はペンダントの下でブルームの塊になる。オフホワイト（#e9e4da）にする。冷蔵庫の中の光は、点光源 0.8・奥の自己発光 0.06 程度まで抑える。
- 取っ手（半トーラス）は z −π/2 で回すと外を向く（+π/2 だとカップの中へ曲がる）。取っ手や注ぎ口の向きは静止画で確認する。
- お湯を淡い青や白にすると牛乳に見え、青から茶色へ補間するとピンクになる。暖かい黄褐色を土台にする。細いクリーム色の流れは棒に見えるので、半径 0.07 以上・自己発光 0.22 にする。

- 香りの帯（`paradise` の Aroma）は、カップに寄ったカットでは幅 0.09 だと茶色い帯に見え、帯にもかかる。細い幅にし、高さは 0.9 以内にする（`cookietea` の Scent）。

### シェーダー・Remotion の落とし穴
- GLSL で `half` は予約語。
- `pow(1-abs(dot(n,v)),k)` は |n·v|>1 で NaN になり、ブルームで大きな黒い四角に広がる。
- 透明な DoubleSide の内側は FLIP_SIDED のパスで描かれる（`gl_FrontFacing` は常に true）。マテリアルごとの `envMapIntensity` は `scene.environmentIntensity` に上書きされる。
- HTML のカードは `whiteSpace: "nowrap"` にする（Layer の中で折り返される）。`background` の一括指定を React が当て直すと `background-clip: text` が消えるので、`backgroundImage` を使う。
- タイムラインの行・チャンクの時刻はシーンからの相対時刻（絶対時刻はシーンの start を足す）。
- 静止画・書き出しが「Timed out … setting up the headless browser」「Timed out loading Google Font」で止まるのは、Zen Maru Gothic の約240個の分割ファイルが Google Fonts から届くのに 18 秒（1ファイルごとの固定の上限）を超えるため。2026-10-28 から `src/koucha/theme.ts` は `public/fonts/zenmaru/`（`node cache-fonts.mjs` で保存したもの）を読むので、ネットに依存しない。消えていたら `cd remotion-composer && node cache-fonts.mjs` を実行する。headless ブラウザは sandbox の中では立ち上がらないので、静止画・書き出しのコマンドは sandbox を外して実行する（`projects/golden_drop_v3`）。

### 音声・文字起こし
- ElevenLabs の画面: 1回の「音声を生成」でテイク1・2ができる。前のパートの音声は「履歴」の行をクリックして下のプレーヤーに読み込み、下のバーのダウンロードボタンで落とす（行のアイコンは形式のメニューが開き、二重にダウンロードしたことがある）。同じ生成の2テイクは同じファイル名（時刻）になり、下のバーのダウンロードはプレーヤーを一時停止しているときしか動かない。1行ずつ落とし、そのたびに ls と md5 で中身が別か確かめる。1回の生成の2テイクはファイル名（作成時刻）が同じになることがあり、また下のバーのダウンロードはプレーヤーが一時停止中でないと効かないことがある。行を1つずつ読み込み、一時停止してからダウンロードし、そのたびに `ls`・md5 で増えたか確かめてからプロジェクトに移す（`projects/cookie_tea`、2026-10-27）。
- テイクのカード（生成:テイク1・2）のダウンロードアイコンは、そのカードのテイクではなく**下のプレーヤーに読み込まれているテイク**を落とすことがある（同じ md5 が2つできた）。また生成中や生成直後はページの高さが変わり、座標でクリックすると「音声を再生成」を押してしまう（1回分のクレジットを失った）。ボタンは座標でなく `find` の ref や JS（`[...document.querySelectorAll('button')].find(b=>b.textContent.trim()==='音声を生成')`）で押す。テイク2は、カードの「再生」を ref で押して読み込み → JS で `document.querySelector('audio').pause()` → 下のバーの「オーディオをダウンロード」（ref）で落とす。生成中（カードにくるくるが出ている間）は、どのダウンロードも効かない。`ls -t ~/Downloads | head` は落としたファイルを上に出さないことがあるので、`ls ~/Downloads/ElevenLabs_*` で探す（`projects/golden_drop_v3`、2026-10-28）。
- 無料プランは月 10,000 クレジット。エディタ下の「〇クレジット残り」は生成しても更新されない（再読み込みしても古いまま）ことがある。生成の前に `https://elevenlabs.io/app/subscription` の「使用済みクレジット」で、台本の文字数（タグ込み、改行込み）が残っているか確かめる。1回の「音声を生成」は2テイクできても文字数の1回分しか減らない（`projects/mimamori_koe`、2026-10-29: 313 字の生成で 1,070→757）。足りるなら確認せずに生成する。足りないときだけ、生成の前にユーザーに伝える（別アカウントへの切り替えはユーザーの操作が要るため。`projects/sns_yuukai`、2026-10-28 はパート3の手前で使い切った）。
- クレジットが切れたら、ユーザーの別アカウントで続きを作れる（パートごとに別アカウントでも、Otani・v4・安定性 50 なら声はそろう）。別アカウントが別の Chrome プロフィールにあるときは、そのプロフィールでブラウザ操作の拡張機能を接続してもらい、切り替える（Claude in Chrome では `list_connected_browsers` → `select_browser`。`tabs_context_mcp` に出るのは自分のタブグループだけで、ユーザーが開いたタブは見えない）。切り替えたら、まず `app/subscription` でアカウントが変わったか確かめ、ボイスを Otani に選び直す（初期値は Adam）（`projects/sns_yuukai`、2026-10-28）。別のプロフィールに切り替えたときも、そのプロフィールで自動ダウンロードが許可されているか先に確かめる（手順3の注意。`projects/english_breakfast`、2026-10-30 はテイク2で止まった）。
- 複数のブラウザ（プロフィール）をつないでいると、どれがどのアカウントか見分けにくい。各ブラウザで `https://elevenlabs.io/app/settings` を開き、JS で `document.body.innerText` からメールアドレスを拾って確かめる。番号は接続し直すと変わりうる。確かめるために開いたタブは、ほかのブラウザのものも切り替えて閉じる（`projects/teabag_shiboru`）。
- 入力の途中でアップグレードのポップアップが出て、文字を飲み込むことがある。「後でリマインド」で閉じて打ち直す。
- ElevenLabs は、子ども＋性的な語を含む文をブロックする（部分返金、1回 約43クレジット）。その種の題材は最初から言い換え（例:「人には見せられないような画像」）、ブロックされたら、その文を言い換えて1回だけ再試行する（許可は要らない）。言い換えてもブロックされたら、そこで止めてユーザーに聞く。
- `script.json` の `spelling` は「Scribe の表記 → 台本の表記」の向きで書く（逆だと文字の対応がずれる）。右側は**読ませる文（チャンクの2つ目、かな）**に合わせる。字幕の表記（1840年ごろ）に合わせると対応しない（`projects/tea_times` で 354/404 字 → 読ませる文に直して 404/404 字）。
- `timing.md` で2つのチャンクが同じ開始時刻になったら、Scribe が台本のかなを漢字で書いた所（いっぽう→一方、ばんごはん→晩ご飯）で対応がずれている。`spelling` に足して `build_timeline.py` をやり直す（`projects/high_tea`）。
- 対応が取れていても、続けて読まれた短いチャンク（「豪華な／アフタヌーンティーを」）は 0.3 秒しか出ない。字幕は前のチャンクとまとめ（「海外のホテルでは豪華な」、11字以内）、`build_timeline.py` をやり直す（`projects/tea_times`）。
- 「音声を生成」のあとに「Starter にアップグレード」のポップアップが出ることがある。購入せず、`find` で「閉じる」の ref を探して閉じてからダウンロードする（`projects/high_tea`、2026-10-29）。
- Scribe は、全体を通した文字起こしで短い数字（1月・2時間）を落としたり、単語を崩したりする。疑わしい所は、その文だけを切り出して確かめてから読みを直す。
- これまで効いた読み: AI→エーアイ、ChatGPT→チャットジーピーティー、３つ→みっつ、20分→にじゅっぷん、黒茶→くろちゃ（「こくちゃ」は緑茶と聞き取られる）、CHAGEE→チャジー、IVE→アイヴ、辛く→からく、主賓→大切なお客さま。
- ユーザーが「最後の〇〇はいらない」と言ったら、そのカットごと消す意味。迷ったら聞く。
- 静止画のコンタクトシートを zsh で作るとき、`xstack=inputs=$n:layout=…` は `$n:l` が zsh の修飾子として読まれて壊れる。`${n}` と書く。この環境の ffmpeg には `drawtext` がない。
